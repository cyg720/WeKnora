# WeKnora 离线源码学习工作台

双击 `index.html` 即可阅读。无需服务、npm 安装、网络或 IDE；迁移时复制整个 `docs_html` 文件夹。

## 信息架构与阅读方案

采用“业务地图 → 关键调用链 → 源码证据 → 版本演进”逐步深入的方式：

- **项目全景**：知识底座、RAG/Agent 两条问答路径及权限边界。
- **从零学习**：九步路线，明确每一步的目标、阅读入口与完成状态。
- **功能清单**：26 个大模块下的业务阅读主题；每个主题有中文作用说明和源码入口。下方提供 HTTP 接口、实现声明、源码文件及测试四种证据视图。
- **调用链导览**：启动、入库、RAG、Agent、共享授权、Wiki、内置助手、协作、定时任务及后台活动十条关键链路；支持逐步聚焦和直接打开代码。
- **源码阅读**：带行号、高亮、声明跳转、词法引用线索、相关测试及 SHA-256 的离线全文快照。
- **智能体扩展**：内置工具、MCP、Skills、沙箱后端、浏览器、模型协议，以及操作目录、统一批准、协作、定时与后台活动的扩展边界与验证维度。
- **架构图谱**：Archify 的架构、时序、工作流、数据流和生命周期五类图（六张图，含定时任务工作流）；支持聚焦、追踪、主题、读者控制的动画及导出。
- **Git 时间线**：所有 HEAD 可达提交；中文类别与影响说明、术语译解、原始标题/正文、父提交、作者/提交日期及文件增删行数。
- **阅读笔记**：本地进度、源码收藏、笔记、JSON 备份和导入。

桌面采用固定侧栏与阅读主区；窄屏采用折叠侧栏。交互包括搜索、筛选、分页、展开、源码对话框、学习进度和主题切换；页面与对话框有过渡，尊重 `prefers-reduced-motion`。

## 证据与覆盖边界

`manifest.json` 记录快照版本、文件哈希、计数和排除项。生成器读取 Git 已跟踪文本文件；不收录未跟踪业务文件、二进制资源、部分锁文件或大于 1.8 MB 的文件。文档图片目录不做全文快照。

业务分类与十条调用链是人工基于源码组织的学习内容。声明、注释、路由变量与引用线索采用词法提取，不等同于 Go 编译器类型信息或完整静态调用图。同名处理器会列出多个候选，无法解析的路由组前缀会标注待核对。接口字段、实际响应和授权最终以注册表达式、处理器、接口和 service/access 实现为准。

每条 Git 提交都有中文类别与受影响模块说明；英文标题采用自动术语译解，**不声称全部记录均经过逐条人工完整翻译**。原文和完整正文保留供核对。合并提交可能没有直接 numstat，不能据此认定没有改动。“当前源码”按钮打开 HEAD 快照，不是历史版本；精确历史补丁用记录中的 `git show <sha>` 命令核对。

## 如何更新

在仓库根目录运行：

```powershell
python -B qishu/docs_html/build_docs.py
```

脚本重新读取当前已跟踪源码和 HEAD 历史，更新索引和快照。它不猜测新业务逻辑，人工主题说明、调用链和图谱规格应随代码变化复审。运行生成器本身不需要 archify、浏览器或其他包。

界面回归测试需要本机 Playwright 与 Chrome；`PLAYWRIGHT_PATH` 可覆盖包路径。图谱维护需要已安装的 archify；`ARCHIFY_CLI` 可覆盖工具路径。当前脚本里的默认路径仅是本次作者环境，**阅读产物完全不依赖这些路径**。

```powershell
node qishu/docs_html/verify_diagrams.mjs
node qishu/docs_html/verify_docs.mjs
```

## 离线适配与验证

archify 2.16 的输出包含 Google 字体链接，且无引导章节时的运行时分支遗漏了 `isPlaying` 方法检查。适配脚本保留原始交付件，只在单独的离线副本移除字体链接并补充方法存在性检查。所有变化和两份 SHA-256 记录在 `*.offline-adapter.json`，不修改已安装的 Skill。

原始交付、离线副本的静态检查、真实浏览器测量和图像审阅是不同验证层，不能互相替代。工作台验证在 `file://` 和浏览器离线模式运行，检查外部请求、JS 错误、源码全文、搜索、筛选、分页、主题、收藏、笔记与窄屏布局。最终结果见 `verification.json`；图谱验收与视觉记录见 diagrams。

本次工作只创建学习文档与维护脚本，没有修改项目运行代码。后端 Go 测试与项目完整构建不属于这份文档的验证结论。
